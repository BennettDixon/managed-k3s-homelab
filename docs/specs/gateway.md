# gateway — v1 specification

**Status: DRAFT for operator sign-off (2026-09-09).** Synthesized from a four-designer panel with opposed lenses (metered-first, subscription-lane-first, identity/blast-radius, operator-toil), a bench critic that settled every disputed fact against the live CLI, the worker, the NAS artifacts and the vendor docs, a design critic that adjudicated the drafts against this repo's rules, and a money red-team that attacked all four ledgers. Nothing here reconciles or spends until slice 2. The nine operator sign-offs are §15, marked **[SIGN-OFF n]** where they bind; three further questions no draft asked are §15's tail. `(verify)` marks a pre-implementation check (§13).

**README paragraph (repo convention):** `gateway` is the model gateway of the personal cloud: an OpenAI-compatible `POST /v1/chat/completions` at `http://gateway/v1/…` (tailnet-only, caller-token gated) that routes every model call of the house onto a lane — the operator's Claude subscription, executed by the unmodified `claude` binary on `worker-01` through a pull protocol whose credential never leaves that box, or the metered Anthropic API — under a per-project budget ledger in one SQLite file on a PVC. Every request carries a caller token, a project and a budget cap; a missing cap is an error, exactly as in jobs-mcp. Depends on: tailscale-operator (exposure), external-secrets (caller-token map, metered key, Harbor robot), Harbor (image), kube-prometheus-stack CRDs, and `worker-01` for the subscription lane only. jobs-mcp executors and future workers are its callers; NanoClaw never is.

**Design stance.** jobs-mcp's failure model — power dies mid-write, any box, any moment; one file, one writer, one transaction per transition; restart is the recovery — plus two invariants this service adds as the first holder of a dollar-spending credential: **money is reserved before a provider is called and settled from what the provider reported, and unknown spend settles at the reservation, never at zero**; and **the subscription credential is consumed only by the unmodified Claude Code binary on the box that minted it** — the gateway never sees, stores or proxies it. The cap is a bound on list-equivalent cost on every lane, so `0` means "no model call anywhere" with no per-lane footnote. Exactly two alerts may wake the operator: the money brake and the spend-rate anomaly; everything else degrades into a morning alert. Errors over surprises: unsupported request fields are rejected by name, never silently dropped. Public-repo safe: MagicDNS names only.

## 1. Backing store and ledger

SQLite, single file `/data/gateway.db`, `journal_mode=WAL`, `synchronous=FULL`, PVC `gateway-data` (1Gi, `local-path`, RWO — unenforced; `gateway_db_bytes` is the real alert); `replicas: 1` + `Recreate` make a second writer structurally impossible (jobs-mcp §8). Unlike knowledge-mcp's index this file is **not a cache**: it is enforcement state. Losing it loses no money, but a fresh PVC reopens every period budget; the Console workspace limit (§7.3) makes that survivable; Litestream to the NAS is the first v1.x task (§11). Migrations additive-only at boot (jobs-mcp §1). Redis rejected again: counters are one `UPDATE` inside the reservation transaction, there is no pub/sub consumer, and a second stateful system on one node adds nothing `synchronous=FULL` does not guarantee. Reopen tripwires: > 50 req/s sustained, a second replica, or a consumer needing pub/sub. **[SIGN-OFF 4]**

**Units.** Money is stored as **integer micro-USD**; prices are stored as integer micro-USD **per MTok** (every current rate is an integer there; a per-token unit is not — cache-read rates are fractions) and each component is `ceil(tokens × price / 1e6)`. Sums and cap comparisons are exact; the interface presents USD; jobs-mcp's `spent_usd` receives a rounded value. **Two bases, never summed together:** `billed` (metered dollars) and `list` (list-equivalent, both lanes).

```sql
CREATE TABLE requests (                        -- one row per admitted request: METADATA ONLY, and it IS the ledger and the log
  id TEXT PRIMARY KEY,                         -- ULID = X-Gateway-Request-Id = the OpenAI `id`
  caller_id TEXT NOT NULL, class TEXT NOT NULL, project_id TEXT NOT NULL,
  job_id TEXT,                                 -- scope key is (caller_id, job_id)
  period TEXT NOT NULL, day TEXT NOT NULL,     -- 'YYYY-MM' and 'YYYY-MM-DD' UTC, FIXED at reserve; settle never recomputes them
  lane_requested TEXT NOT NULL, lane_used TEXT, fallback INTEGER NOT NULL DEFAULT 0,
  model TEXT NOT NULL, model_used TEXT,        -- registry alias; provider-reported id (CLI lane: modelUsage keys)
  state TEXT NOT NULL,                         -- reserved | settled | released | timeout | aborted | swept
  cap_presented_micro INTEGER NOT NULL,        -- X-Gateway-Budget-Cap-USD as presented (a JOB cap when job_id is set)
  reserved_micro INTEGER NOT NULL,             -- billed worst case (0 on the subscription lane)
  settled_micro INTEGER,                       -- billed actual; = reserved_micro for timeout | aborted | swept
  list_reserved_micro INTEGER NOT NULL,        -- list worst case, both lanes
  list_micro INTEGER,                          -- list actual, floored (§6.2)
  input_tokens INTEGER, output_tokens INTEGER, cache_write_5m_tokens INTEGER,
  cache_write_1h_tokens INTEGER, cache_read_tokens INTEGER, inference_geo TEXT,
  max_tokens INTEGER NOT NULL,                 -- as sent or the registry default; never unbounded
  upstream_started INTEGER NOT NULL DEFAULT 0, -- message_start seen (or CLI launched) ⇒ never release
  error_code TEXT, http_status INTEGER, provider_request_id TEXT, latency_ms INTEGER,
  worker_id TEXT, lease_expires_at INTEGER,    -- subscription lease
  reserved_at INTEGER NOT NULL, settled_at INTEGER
);
CREATE INDEX idx_req_scope  ON requests(project_id, period, state);
CREATE INDEX idx_req_day    ON requests(caller_id, day, state);
CREATE INDEX idx_req_job    ON requests(caller_id, job_id) WHERE job_id IS NOT NULL;
CREATE INDEX idx_req_window ON requests(project_id, lane_used, reserved_at);    -- rolling windows over REQUESTS
CREATE INDEX idx_req_lease  ON requests(state, lane_used, lease_expires_at);
CREATE TABLE job_caps (caller_id TEXT NOT NULL, job_id TEXT NOT NULL, cap_micro INTEGER NOT NULL,
                       first_seen INTEGER NOT NULL, PRIMARY KEY (caller_id, job_id));   -- the job-cap pin
CREATE TABLE lane_state (lane TEXT PRIMARY KEY, last_heartbeat INTEGER, cooling_until INTEGER, auth_ok INTEGER NOT NULL DEFAULT 1);
CREATE TABLE brakes (lane TEXT PRIMARY KEY, tripped_at INTEGER, reason TEXT, reset_at INTEGER, reset_by TEXT);
CREATE TABLE meta (k TEXT PRIMARY KEY, v TEXT);   -- schema_version, last_commit_ts (clock guard), prices_hash
```

**No column can hold prompt or completion text, a prompt hash, or the OpenAI `user` field** — the request-log posture (§9.3) is structural. Refusals are a counter, not rows. Spend over a scope = `Σ settled_micro` over `settled | timeout | aborted | swept` + `Σ reserved_micro` over `reserved`; **in-flight reservations count against every cap until settled.** Row size ≈ 400 B; 1,000 requests/day ≈ 150 MB/year; pruning is an explicit destructive task, never automatic.

**Transaction boundaries.** One connection; **`BEGIN IMMEDIATE`** for every money transition — the concurrency guarantee is a property of one synchronous connection plus the immediate lock, not of SQL, and the spec says so because a language switch could silently lose it: an implementation whose SQLite binding runs the `SELECT SUM` outside the write transaction (Python's stdlib default isolation) is a check-then-insert overdraw and MUST instead use a materialized scope-totals table with a single conditional `UPDATE … WHERE held + settled + W <= cap` and `changes() == 1`. *Reserve* (one transaction, before any upstream socket): validate → compute the worst case on both bases → `INSERT OR IGNORE job_caps`, read it back, mismatch ⇒ rollback `409 E_JOB_CAP_MISMATCH` → check every applicable scope (§5) ⇒ else rollback `402` → `INSERT requests (state='reserved')` → commit. The upstream client is constructed only inside this choke point — no code path reaches a provider without a row. *Settle* (one transaction): `UPDATE requests … WHERE id=? AND state='reserved'`, `changes()==1` or no-op (a late or duplicate completion is logged, never re-settled), keyed by the **row's** `period`/`day`, never `now`. *Release* only when `upstream_started = 0` **and** the provider outcome proves no generation (connection refused before the body; 4xx/429/529 before `message_start`). A 2xx with an unparseable body, a timeout, a severed stream, a client abort or a lane-agent death ⇒ settle at the reservation (`timeout` | `aborted`).

**Power dies mid-write.** Intent is durable before the side effect (jobs-mcp §5): with one process, any `reserved` row found at boot is by definition an orphan. Boot sweep **before `listen`**: `WHERE state='reserved' AND reserved_at < boot_ts` ⇒ `swept`, `settled_micro = reserved_micro`, `list_micro = max(list_reserved_micro, floor)`; `gateway_swept_usd_total` increments and `GatewaySweptSpend` fires. Over-counting is the safe direction, bounded by one worst case per orphan; reconciliation against the Console is a runbook line. Then `PRAGMA quick_check`; failure ⇒ readiness false. **Clock guard:** `meta.last_commit_ts` is updated in every money transaction; while `now < last_commit_ts − 60 s` readiness is false and no reservation is admitted (a node booting on a stale RTC after a power cut must not reopen a period), and no row's `period` may sort before the last committed row's.

## 2. Transport, exposure, auth

- **Transport:** plain HTTP on 8080, JSON; the tailnet (WireGuard) is the transport security; no non-tailnet path exists. Body limit 1 MiB (a 200K-token prompt ≈ 800 KiB; larger cannot be reserved sanely ⇒ `413`). Server timeout 600 s. Every upstream call **streams** through the SDK helper so undici's 300 s headers timeout — the jobs-mcp lesson — never severs a call mid-spend.
- **Exposure:** ClusterIP `gateway` (label `app: gateway`) + `tailscale.com/expose: "true"` + `tailscale.com/hostname: gateway` ⇒ `http://gateway/v1/…`; clients set `OPENAI_BASE_URL=http://gateway/v1` and `OPENAI_API_KEY=<caller token>` — **the caller token is the client's `api_key`; zero client changes.** No tailnet node named `gateway` exists today `(verify at slice 2; MagicDNS would silently mint gateway-1)`. Compute-site placement: the only node, same site as `worker-01`, so the pull lane is LAN-local. **[SIGN-OFF 2]**
- **Auth — the house shape, second consumer [SIGN-OFF 7].** One SM secret `k3s_gateway_caller_tokens` = JSON map `{caller_id: token}` (terraform → ExternalSecret with no `property` → env `GATEWAY_CALLER_TOKENS`, knowledge-mcp's manifest verbatim), parsed at boot with knowledge-mcp's `parseCallerTokens` rules (id regex, ≥ 16 chars, duplicate values refused, offending key never echoed), resolved by its `auth.ts` (constant-time compare over every candidate; a token whose id has no registry entry authenticates nobody). Policy lives in the repo registry (§4), never in the secret. `Authorization: Bearer` on every request.
- **Classes — a deny-by-default capability table dispatched before any handler:**

  | class | routes | notes |
  |---|---|---|
  | `operator` | `/v1/*`, `/ledger/*` | workbench sessions; all granted projects; the only class the subscription lane is granted to in v1 |
  | `executor` | `/v1/*` | n8n executors; `X-Gateway-Job-Id` REQUIRED; granted projects only; `max_request_cap_usd` required |
  | `worker` | `/v1/*` | build-order item 5's queue consumers; reserved, not minted in v1 |
  | `lane-agent` | `/lane/*` only | the subscription pull agent on `worker-01`; can never spend a dollar |

  The enum is **closed at registry admission — there is no `frontend` value and no way to declare one**; a PR adding one fails CI, then readiness. NanoClaw is fenced structurally: never in the map, never in the registry, no class it could be granted, and (recommended, appliance-tier operator task) omitted from any future ACL grant list to `gateway:80`. A NetworkPolicy ingress fence is a **later PR** gated on a scratch-namespace enforcement test (§11) — never a fence the repo documents without proving.
- **Rotation, one credential per principal per window:** tfvars → targeted apply → ESO refresh (≤ 1 h or `force-sync`) → `kubectl -n gateway delete pod -l app=gateway` (map read at boot; Recreate) → update the holder (workbench env; `/etc/n8n/n8n.env` + restart; `worker-01` `/etc/worker/gateway.env` + unit restart). A stale holder fails loudly (`401`; the lane agent's gauge drops ⇒ alert).
- **The n8n trust domain.** Every workflow author reads `$env` (`proxmox/n8n.md`), so `GATEWAY_EXECUTOR_TOKEN` identifies *n8n-as-executor*, not a workflow. The env therefore holds exactly one gateway token, class-scoped: one project, job id mandatory, `max_request_cap_usd` in cents, bounded by the project's monthly cap. The gateway cannot verify that a job id is real (jobs-mcp offers no lookup); the job-cap pin (§1) stops escalation, and the signed-grant seam (§11) closes invention.
- **WhoIs / tagged identities.** Requests arrive from the operator proxy pods; the pod sees the proxy address, never the caller — WhoIs is a named middleware seam, not a v1 control. The pull direction needs no ACL change: `worker-01` reaches `http://jobs-mcp/healthz` and `http://knowledge-mcp/healthz` today (bench, 2026-09-09).

## 3. Interface

| route | class | purpose |
|---|---|---|
| `POST /v1/chat/completions` | operator, executor, worker | the product |
| `GET /v1/models` | same | models the caller's *project* allows, with `lanes` and `max_tokens` |
| `POST /v1/embeddings` | same | declared; **`501 E_UNSUPPORTED` in v1** (§11) so the client shape is settled |
| `GET /ledger/projects/{id}` · `GET /ledger/jobs/{id}` · `GET /ledger/requests?project=&since=` · `GET /ledger/lanes` | operator (executors: own jobs only) | budgets, job spend (executors read `spent_usd` here), metadata rows, lane state |
| `POST /ledger/brake-reset {lane, reason}` | operator | audited in `brakes` |
| `POST /lane/claim` · `/lane/heartbeat` · `/lane/complete` | lane-agent | §6.2 |
| `GET /healthz` · `/readyz` · `/metrics` | none | §8 |

`/lane/*` and `/ledger/*` sit outside `/v1/*` so the OpenAI surface stays exactly OpenAI. **[SIGN-OFF 6]**

**Headers on `/v1/chat/completions`:**

| header | rule |
|---|---|
| `Authorization: Bearer <token>` | required; `401 E_UNAUTHORIZED` |
| `X-Gateway-Project` (alias: the SDKs' native `OpenAI-Project`; both present and different ⇒ `400`) | required; unknown and ungranted are the same `403 E_FORBIDDEN` (no existence oracle) |
| **`X-Gateway-Budget-Cap-USD`** | **required, no default, ever** — finite, ≥ 0, ≤ min(`MAX_REQUEST_CAP_USD`=25, the caller's `max_request_cap_usd`); missing ⇒ `400 E_BUDGET_CAP_MISSING`, malformed ⇒ `400 E_BUDGET_CAP_INVALID` (jobs-mcp §3 verbatim). **`0` is legal and is refused at admission on every lane** — it means "no model call permitted". With a job id it is the JOB's cap: cumulative over `(caller_id, job_id)` and pinned by the first request (`409 E_JOB_CAP_MISMATCH` on a different value). |
| `X-Gateway-Job-Id` | `^[A-Za-z0-9._-]{1,64}$`; required for class `executor` |
| `X-Gateway-Lane: subscription \| metered` | optional; absent ⇒ the project's `default_lane`; `subscription` PINS the lane (never converts to spend) |
| `X-Gateway-Fallback: metered` | optional; fallback happens only with this header AND the project's `fallback_allowed` (§6.3) |
| `X-Gateway-Timeout-S` | default 280, max 280 on the subscription lane (headers-timeout bound); default 300, max 600 on metered |

**Body — the accepted OpenAI subset (everything else is `400 E_UNSUPPORTED` naming the field):** `model` (registry alias or id; `E_MODEL_UNKNOWN`; absent ⇒ the project's `default_model`), `messages` (`system`/`developer` hoisted into one system prompt; `user`/`assistant` text parts only), `max_tokens` / `max_completion_tokens` (absent ⇒ the model's `default_max_tokens`; ≤ its `max_tokens`; **never clamped** — a cap that cannot cover the worst case is refused with `affordable_max_tokens`), `stop` (metered only, ≤ 4), `response_format` (`json_object` ⇒ instruction; `json_schema` ⇒ Anthropic structured output on metered, `--json-schema` on the CLI lane), `reasoning_effort` (`low|medium|high` + `xhigh|max` extension values ⇒ `output_config.effort` / `--effort`), `stream` (honoured as a **buffered** stream: one content chunk then `[DONE]`, header `x-gateway-stream: buffered`, on both lanes — headers go out first, so no client dies at 300 s waiting), `user`/`metadata`/`store` (ignored, never recorded). **Stripped with `X-Gateway-Ignored: temperature,top_p,presence_penalty,frequency_penalty`** rather than rejected: current models return 400 on sampling parameters and every stock OpenAI client sends a temperature by default. **Rejected by name:** `n > 1`, `tools`/`functions`/`tool_choice`, `logprobs`, `logit_bias`, `seed`, `modalities`, `audio`, `prediction`, `service_tier`, image/file/audio parts, any Anthropic server tool.

**Response:** a standard `chat.completion` (`id: chatcmpl-<ulid>`, `choices[0].message.content`, `finish_reason` `stop|length|content_filter` — `refusal` maps to `content_filter` and is still settled from usage; `usage.prompt_tokens/completion_tokens` + `prompt_tokens_details.cached_tokens`) plus headers mirrored in a `gateway` extension object: `X-Gateway-Request-Id`, `X-Gateway-Lane-Used`, `X-Gateway-Billed-USD` (metered dollars; `0` on the subscription lane), `X-Gateway-List-USD`, `X-Gateway-Job-Spent-USD` (cumulative, list basis, when a job id is present — what an executor reports as `spent_usd`), `X-Gateway-Project-Remaining-USD`, `X-Gateway-Fallback-From`, `X-Gateway-Ignored`.

**Errors** use the OpenAI envelope `{"error": {"type", "code": "E_*", "message", "param", "retryable"}}`:

| code | HTTP | meaning |
|---|---|---|
| `E_UNAUTHORIZED` / `E_FORBIDDEN` | 401 / 403 | bad token; project, model or lane not granted; executor without a job id |
| `E_SCHEMA`, `E_UNSUPPORTED`, `E_MODEL_UNKNOWN`, `E_BUDGET_CAP_MISSING`, `E_BUDGET_CAP_INVALID` | 400 | validation; no row |
| `E_JOB_CAP_MISMATCH` | 409 | a known job presented a different cap; no row |
| **`E_BUDGET_EXCEEDED`** with `scope ∈ {request, job, caller_day, project_period, window, brake_metered, brake_subscription}`, `remaining_usd`, `would_reserve_usd`, `affordable_max_tokens` | **402**, `retryable: false`, **`x-should-retry: false`** | every ledger refusal — no OpenAI SDK retries 402; 429 is retry-amplified; refusals cost nothing and write no row |
| `E_LANE_COOLING` | 429 + truthful `Retry-After` | subscription window/cooling — a short retry can succeed |
| `E_UPSTREAM_RATE_LIMITED` | 429 (provider `retry-after` passed through) | reservation released; a rate limit is not an outage |
| `E_LANE_UNAVAILABLE` | 503 + `Retry-After` | lane down, cooling, agent absent, workspace limit reached; **no reservation** |
| `E_UPSTREAM_AUTH` / `E_UPSTREAM_ERROR` / `E_WORKER_CONTRACT` | 502 | provider 401/403 (lane down within one request); 5xx/network before generation (released); worker report violated the contract (settled at the reservation) |
| `E_TIMEOUT` | 504 | settled at the reservation |
| `E_LEDGER_UNAVAILABLE` / `E_INTERNAL` | 503 / 500 | SQLite write failed ⇒ no call (fail closed); details logged, never leaked |

A monthly runbook line reconciles `Σ billed` against the Console; > 10 % apart reopens the price table.

## 5. Budget model **[SIGN-OFF 5]**

- **Unit of account: list-equivalent USD on every lane.** Metered `list == billed`; subscription `billed = 0`, `list` charged. One number, one meaning: `X-Gateway-Budget-Cap-USD: 0` forbids every model call on every lane (jobs-mcp's "0 = no model spend permitted" holds verbatim), and fallback never changes what a cap means — it changes the *bill*, which §6.3 bounds. Billed dollars are tracked in their own column and are what the monthly project cap, the daily money brake, the Console limit and the money alerts use. Quota consent for the free lane, should it ever need to differ from the cap, is an additive header later — not a v1 footnote.
- **A project** is a registry-declared spending scope with a hard period cap: an accounting identity, deliberately not a Kubernetes or tailnet identity. A **caller** is a token; a **job** is `(caller_id, X-Gateway-Job-Id)`.
- **Caps, tightest wins, all checked in the reservation transaction:** the pinned job cap (or the request cap without a job) on both bases; the project period cap (calendar month UTC — Console granularity, no timezone toil) on `billed`; the subscription windows (5 h / 7 d, `list`, summed over *requests* at their `reserved_at`, never over entries — entry-time sums go negative at a boundary); the two env brakes `GATEWAY_METERED_DAILY_CEILING_USD` (default 5, billed) and `GATEWAY_SUBSCRIPTION_DAILY_LIST_CEILING_USD` (default 10) — gateway-wide, one number each, trip ⇒ that lane answers `402 scope=brake_*` until 00:00 UTC or an audited `brake-reset`; and the Console workspace limit outside the code. A tripped brake is one of the two 3 am pages. Never raise the env ceiling to make a page stop: find the offender in `/ledger/requests`, cancel it at jobs-mcp, then reset.
- **Reservation = the request's maximum possible charge, computed before any provider is called.** Metered: `in = ceil(count_tokens × 1.05) + 32` (the endpoint is free, has its own rate bucket and is documented as an estimate; the margin is monitored) with `ceil(bytes / 2.5)` as the fallback when `count_tokens` fails (a `count_tokens` outage degrades accuracy, never availability); `W_billed = in × input_price + max_tokens × output_price`, × 1.1 if the workspace is pinned to US inference `(verify: usage.inference_geo)`; v1 sends no `cache_control`, so no write rate enters; thinking tokens bill as output inside `max_tokens`. **Provably ≥ settle** under those assumptions; `settled > reserved` is still settled at actual and increments `gateway_settle_over_reserve_total` — the invariant is monitored, not assumed. Subscription (`W_list` only; `W_billed = 0`): `harness_overhead_tokens` at the 1 h cache-write rate + `in × input_price` + `default_max_tokens × output_price`. This is the one place the reservation is a **soft** bound: the CLI ignores `max_tokens`, makes hidden helper calls, and `--max-budget-usd` is passed as a belt whose binding under subscription auth is undocumented `(verify in slice 4)`; an overrun settles at actual, blocks the caller's next call, and is bounded by the windows and the daily list brake. Quota is not money; the honest worst case is stated rather than pretended.
- **Settle** from provider-reported usage only (metered: `message_start` input/cache fields + final `message_delta` output; CLI lane: §6.2), each component `ceil`; refusals write nothing and call nothing.
- **Composition with jobs-mcp — zero jobs-mcp code changes.** The executor forwards the job's `budget_cap_usd` as `X-Gateway-Budget-Cap-USD` and its `job_id`; every call and retry attempt under one job shares one pinned cap; the executor reports `spent_usd` = the job's list-basis sum (`X-Gateway-Job-Spent-USD`, or `GET /ledger/jobs/{id}`), and jobs-mcp stores it verbatim (`dispatcher.ts` keeps `report.spent_usd ?? null`, `z.number().nullish()`) — `spent_usd` goes non-null for the first time in slice 3. `budget_cap: 0` (every deterministic task type today) is refused at admission with a `402`, the slice-3 negative proof.
- **What a compromised credential can spend — the numbers the operator signs:**

  | credential | per request | per day | per period | bound by |
  |---|---|---|---|---|
  | `operator` token (workbench) | $5.00 | $5 billed / $10 list (brakes) | Σ granted caps, $21/month | registry ceilings + brakes |
  | `n8n-executor` token (n8n env) | $0.10 | $5 billed (brake) | `gateway-smoke` $1/month | class scoping |
  | `worker-01` lane token | $0 | $0 | $0 | class has no `/v1/*`; can read queued operator prompts and fabricate text; forged usage settles at the floor (§6.2) |
  | gateway pod / metered key leak | — | — | Console workspace limit ($50/month) | Anthropic-side; rotation §7.4 |
  | `worker-01` OAuth token | $0 billed | subscription quota | — | personal credential; revoked at the account |

## 6. Lanes **[SIGN-OFF 3] [SIGN-OFF 6] [SIGN-OFF 9]**

**6.1 Metered lane.** The official Anthropic SDK against the native Messages API (never the vendor's OpenAI-compatibility endpoint as the southbound: it hides the cache-token split the ledger prices, ignores `reasoning_effort`, and silently drops unsupported fields — the opposite of §3's stance; the OpenAI shape stays northbound only), `max_retries: 0` — one provider call per ledger row, because the SDK's own retries of timeouts and 5xx hide billed generations under one reservation; the gateway itself retries exactly once, only on a `429` with `Retry-After ≤ 10 s` or a connection refused before the request body was sent — never on a timeout or a severed body, which may already have billed. Always streams upstream (§2). Per request: `messages.countTokens` → reserve → `messages.create({model, system, messages, max_tokens, stop_sequences?, output_config?: {effort, format}, service_tier: "standard_only"})` `(verify the field names at slice 2's first live call)`; never `speed`, never `cache_control`, never a `thinking` override, never `metadata`; the provider `request-id` lands in the row; `model_used` = the provider-reported id. Key from `k3s_gateway_anthropic_api_key` (§7) via explicit env — never the SDK's ambient credential resolution — against one hard-coded base URL (the in-code egress fence; no egress-policy precedent exists). **Error mapping:** 429 with `retry-after` ⇒ `E_UPSTREAM_RATE_LIMITED`, released, lane stays up; org/workspace spend limit (a 429 without `retry-after`, or the 400 a self-set limit returns `(verify)`) ⇒ `E_LANE_UNAVAILABLE`, lane down until the stated resume time else re-probed hourly, alert; 401/403 ⇒ `E_UPSTREAM_AUTH`, lane down; 500/529/network before `message_start` ⇒ released, three consecutive in 5 min ⇒ lane down with backoff 2 s·2ⁿ (cap 2 min), requests get `503` at once with no reservation; any error after `message_start`, any 2xx with an unparseable body, any timeout ⇒ settle at the reservation. **Idle probe:** `models.list()` — authenticated, unbilled, no token-counting bucket — every 5 min while up, every 60 s while down, so a revoked key or a dead network is seen without spending (the idle-bridge-probe lesson).

**6.2 Subscription lane = a pull agent on `worker-01`; the credential never enters the cluster [SIGN-OFF 2].** The OAuth token from `claude setup-token` stays root-only in `/etc/worker/claude.env` and **never enters terraform, Secrets Manager, ESO or any pod** — on the secret path it would be readable by the ESO identity and reconstructable from state; proxying it into direct API calls is the harness-spoofing pattern the vendor enforces against. Push was rejected (an ACL grant, an egress Service with a never-committed FQDN, a listener on the worker, the smoke-era root-ssh revived); pull needs none: the worker opens every connection, to `gateway` only, and reaches `tag:k8s` Services today with no ACL change.

- **Protocol (`/lane/*`, class `lane-agent`, every write idempotent):** `POST /lane/claim {worker_id, cli_version, wait_s ≤ 25}` long-polls; one transaction moves the oldest eligible `reserved` subscription request to a lease (`worker_id`, `lease_expires_at = now + 60 s`, `upstream_started = 1`) — intent durable before the side effect; one lease per worker; `cli_version` below the registry's pinned version ⇒ `426` and the worker is never leased. `POST /lane/heartbeat` every 20 s extends 60 s or returns **`410 Gone`** (expired, caller disconnected, gateway restarted) ⇒ the agent kills the CLI process group at once. `POST /lane/complete` (byte-capped at 256 KiB and schema-validated before any field is read — the dispatcher's `readBodyCapped` precedent — so a rogue agent cannot OOM the pod that holds the dollar key) returns `200`, `200 {duplicate: true}` on a repeat, `410` if the lease is gone (the usage is still recorded as an audit line, never re-settled). **The worker sees only `{request_id, model, system_prompt?, prompt, json_schema?, effort?, timeout_s}`** — never caller, project, job, budgets or the metered key. It returns `{outcome, result_text | structured_output, cli: {subtype, is_error, num_turns, stop_reason, duration_ms, duration_api_ms, total_cost_usd, usage, modelUsage, permission_denials, api_error_status}, stderr_tail ≤ 2 KiB, cli_version}`.
- **Contract checks on the gateway:** `num_turns == 1`, `permission_denials == []`, `modelUsage` non-empty on success, every `costBasis == "list"`; a violation is `E_WORKER_CONTRACT`, settles at the reservation, and marks the lane `degraded` until the next clean result. **Settle:** `list = max(Σ costUSD recomputed from the reported token counts × registry list prices, floor)` with `floor = harness + in × input_price` — the seven NAS artifacts reprice to < 1e-9, so a report whose numbers disagree is refused; under-reporting is pointless, over-reporting is bounded by the per-call maximum. `is_error` with zero usage (the auth-failure signature: `"Not logged in"`, `total_cost_usd: 0`) ⇒ lane `auth_failed`, reservation released. Partial-usage errors settle from `total_cost_usd`/`modelUsage`. A zeroed crash result, an absent `modelUsage` on success, or a `costBasis ≠ list` ⇒ settle at the reservation. **The lane is never allowed to run unmetered.**
- **Lifecycle:** lease expiry (agent or worker died mid-call, power cut) ⇒ settle at the reservation, `504 E_TIMEOUT` to the caller — **no automatic re-lease; a retry is a second spend and the caller's decision.** Caller disconnect ⇒ `reserved` rows cancel at once, leased rows at the next heartbeat (`410`). Gateway restart ⇒ the boot sweep settles every leased row at the reservation; nothing is re-run for a caller whose connection died with the pod (every Recreate deploy would otherwise burn quota twice). End-to-end bound 280 s (the undici headers timeout of any Node caller is 300 s).
- **Pull agent (`workers/gateway-agent/`, deployed like `smoke.sh`):** a single-file, dependency-free program (language per [SIGN-OFF 1]; Python 3.11.2 and Node 24 are both on `worker-01`) under systemd as unprivileged user `gwworker`, `EnvironmentFile=/etc/worker/claude.env` (root-owned; systemd reads it, the agent process inherits the variable — this changes the token's documented posture from "root-only file" to "root-only file, held in one unprivileged process's memory": recorded in `proxmox/worker.md` at slice 4) and `/etc/worker/gateway.env` (`GATEWAY_URL`, `GATEWAY_LANE_TOKEN`, `WORKER_ID`). Loop: claim → run → complete; backoff 2 s·2ⁿ (cap 60 s) on gateway errors. **Invocation — bench-verified flag set (2026-09-09, CLI 2.1.247), prompt on stdin, never argv:**

  ```
  claude -p --output-format json --tools "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
    --permission-mode dontAsk --no-session-persistence --model <cli_alias> \
    [--system-prompt <s>] [--json-schema <schema>] [--effort <e>] --max-budget-usd <list cap remaining>
  ```

  **Never `--bare`** — its help text on both CLI versions says auth is then strictly `ANTHROPIC_API_KEY` and OAuth is never read: the flag turns the $0 lane into a permanently unauthenticated one (two panel drafts had it; the bench caught it). `--max-turns` is in the reference but absent from `--help` on 2.1.247 and is not relied on; the `num_turns == 1` contract check is the runtime fence. **`--fallback-model` is never passed: a cheaper model is a different answer and a silent substitution is a ledger lie.** The agent refuses to start unless the pinned version's `--help` lists every flag it will pass. cwd = a fresh empty `mkdtemp` (no CLAUDE.md, `.mcp.json` or `.claude/` to discover), `HOME` = an empty per-service directory, a **constructed** child environment of exactly `PATH, HOME, CLAUDE_CODE_OAUTH_TOKEN, DISABLE_AUTOUPDATER=1, CLAUDE_CODE_SKIP_PROMPT_HISTORY=1`, a wall-clock kill at `timeout_s`. Unit hardening: `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX`, `MemoryMax=1G`, `TasksMax=64`, `Restart=always`, `After=tailscaled.service`. **The invocation is the injection fence:** with no tools and no MCP servers, an injected instruction has nothing to call; a tool attempt surfaces as `permission_denials`/`num_turns > 1` and fails the contract; the agent is not an LLM, so a prompt cannot make it read files, and the token is never in a prompt, a result or a log. Session files, prompts and results never touch the worker's disk.

**6.3 Routing and fallback [SIGN-OFF 3].** Routing runs once, at admission, and is recorded in `lane_used`. Eligibility: the subscription lane needs the caller's class **and** the project **and** the model to allow it (v1 grants it to `operator` only; widening is a registry PR that reopens SIGN-OFF 9), a request the CLI can honour (§6.4), lane state `healthy`, and window headroom; the metered lane needs `cap > 0` on the billed basis, period headroom and a healthy lane. `X-Gateway-Lane: subscription` ⇒ that lane or `503`/`429` — never spend. **Fallback to metered happens only when the project has `fallback_allowed: true` AND the request carries `X-Gateway-Fallback: metered` AND the reservation passes at metered worst case**; it records `fallback = 1`, sets `X-Gateway-Fallback-From`, increments `gateway_fallback_total` and fires `GatewayFallbackSpend` within the hour. `auto` is rejected at admission — the one policy this spec refuses to make configurable. Which lane paid must never depend on registry state the caller cannot see at call time: the header is one `default_headers` line for an unattended worker, so a worker-outage night is answered by configuration, not by silent conversion — and a lane agent that fakes quota exhaustion or inflates usage can move no request that did not opt in. Mid-request lane switching is not offered.

**6.4 What the headless-CLI lane cannot honour, stated so nobody guesses:** exact multi-turn structure (`messages[]` flatten into `--system-prompt` + one delimited transcript on stdin — declared, identical on both lanes so lane choice never changes semantics), `max_tokens` as a hard bound (advisory; §5), `stop`, `n`, `logprobs`, tool schemas, token streaming, exact model ids beyond `cli_alias`, exact usage isolation (a hidden Haiku helper call is recorded, not hidden), an `assistant` prefix turn. Honoured: model, system prompt, effort, one user message, JSON schema output.

**6.5 Terms and quota [SIGN-OFF 9] — mechanism only.** This spec records no interpretation of another party's terms and no quota numbers beyond the registry's own list-USD windows: a public repo is the wrong place for either. What the repo can guarantee: the credential is consumed only by the unmodified Claude Code binary on the box that minted it (`claude setup-token` exists for exactly this), it is never intermediated, the lane is `operator`-class only in v1, volume is bounded in list-USD by registry numbers and the daily brake, quota exhaustion cools the lane (`cooling_until = now + 30 min·2ⁿ`, cap 5 h) and never converts to spend without §6.3's double consent, and token expiry shows as `auth_ok = 0` ⇒ `GatewayLaneAuthFailed` (rotation: `claude setup-token` in any browser, paste on the worker, restart the unit — about two minutes; no upstream expiry story exists). The operator's attestation is one line in this spec's approval block plus a STATUS decisions-log entry; the vendor's own channel for the question is a recommended operator step before slice 4, its answer recorded when it arrives. Whatever the answer, it changes routing (slice 4 skipped, `lane: subscription` ⇒ `503`), never architecture: slices 1–3 stand on the metered lane.

## 10. Failure matrix

| Failure | Outcome | Mechanism |
|---|---|---|
| Power cut before the reservation commits | no row, no call; the caller retries as a fresh request | one transaction |

## 11. v1 does NOT (reasons and reopen tripwires)

- **Token streaming** (buffered only): no v1 consumer needs incremental output. Tripwire: the first interactive consumer, or a task needing `max_tokens > 16000`.
- **Tools / function calling** on either lane: the largest translation surface and a second billing shape; agentic loops run inside `claude -p` today. Tripwire: the first task type that cannot do its job with single-shot completions.
- **`/v1/embeddings`** (declared `501`): Anthropic offers no embeddings endpoint; knowledge-mcp S1 plans a local CPU model. Tripwire: knowledge-mcp S2 choosing an API embedding backend.
- **Images, documents, audio, server tools, batches:** costs the ledger cannot pre-reserve. Tripwire: the first multimodal job; > 1,000 non-interactive requests/month (batches halve the price).
- **`cache_control` pass-through:** the worst case would need the 1 h write rate. Tripwire: a project whose monthly input spend exceeds 30 % of its cap with repeated prefixes.
- **Idempotent replay of completions:** would require storing completion text (§9.3). Tripwire: a job observed making > 2× its expected gateway calls. Corollary for `gateway-smoke`: `idempotent: true` means "a re-run is bounded by the job cap, not free" — the executor reads `/ledger/jobs/{id}` before calling and, on an existing settled row, reports the spend without calling again.
- **Local lane, multi-provider, per-model sub-caps, daily/rolling money windows, allowed-hours windows:** each a registry field when its trigger arrives (local: a machine with an accelerator joins the tailnet).
- **Signed grants (the jobs-mcp seam):** jobs-mcp attaches `HMAC(webhook_secret, job_id|task_type|attempt|budget_cap_usd)` to the dispatch body (~10 additive lines with a secret it already holds), the executor forwards it as `X-Gateway-Grant`, and the `executor` class then requires it — a workflow author can spend only what the queue issued. Tripwires: a second executor caller, or the first nonzero-cap `frontend_allowed` task type. Two sibling seams on the jobs side: bound `spent_usd` in `CompletionReportSchema` (today `z.number().nullish()` accepts anything), and a per-entry undici `headersTimeout` so `timeout_s` can exceed 300 s for gateway-calling task types (until then: the executor's gateway timeout must be shorter than `timeout_s`, and the executor checks the job ledger before calling, or attempt 2 is refused against a held cap while attempt 1 finishes).
- **NetworkPolicy ingress fence** (`tailscale` namespace + Prometheus only): own PR after a scratch-namespace test proves k3s enforces and probes pass — never documented before proven.
- **Redis**, **Litestream** (the DR seam; needs a NAS user — appliance-tier), **multi-replica**, **WhoIs / identity headers**, **per-caller rate limits**, **automatic Console reconciliation** (Admin API — a broader credential for a v1 non-feature; tripwire: > 10 % ledger-vs-invoice delta), **content capture of any kind** (not a tripwire: a rule), **ledger pruning** (a human task).

## 15. SIGN-OFFS — nine, recommendation first, the alternative's cost second

1. **Language.** *Recommend TypeScript for the pod, the lane agent in the operator's language, and a house decision for all future services made now* (§12). Alternative — Python for the pod: bounded and enumerated (+1 CI workflow and guard port, +1 base image to track, ~35 transitive packages, six house idioms forked, ~100-finding review corpus lost, the compare-and-add ledger form mandatory); its one gain is stdlib SQLite. Legitimate if the operator values reading his own gateway over the fork — then decide it for everything.
2. **Placement.** *k3s pod at the compute site; the subscription lane as a worker-side pull agent on `worker-01`; the OAuth token never in SM, ESO or a pod.* All four designers agreed. Alternatives — the gateway on `worker-01` (no Flux/ESO/Prometheus/Harbor, the ledger on a box that reboots on residential power); push to the worker (an ACL ask, an egress Service, a listener); the token proxied into the cluster (rejected outright).
3. **Lane routing and fallback.** *Lane header optional ⇒ the project's `default_lane`; `subscription` pins and never converts to spend; fallback only with the project's `fallback_allowed` AND a per-request `X-Gateway-Fallback: metered`; `auto` rejected; every fallback is a row, a counter and an alert.* Alternatives — no fallback ever (worker-outage nights fail jobs); automatic fallback (the 3 am bill, and a rogue agent can trigger it); a required lane header (a forgotten header becomes a 400 instead of the registry's declared default).
4. **Ledger store.** *House SQLite (WAL, FULL, one writer, `BEGIN IMMEDIATE`), integer micro-USD, one row = one attempt = the ledger = the log; Redis stays parked with the §1 tripwires.* Alternative — Redis/Postgres: a second stateful system on one node for microsecond-scale serialization; the durability story gets worse.
5. **Budget model.** *List-equivalent USD is the unit on every lane, so `0` forbids every model call everywhere and stays legal at validation; billed dollars tracked separately; three caps tightest-wins plus the two daily brakes plus the Console limit; reserve-then-settle at a `count_tokens`-exact worst case on metered (soft bound on the subscription lane, stated); job caps pinned and cumulative across attempts; never clamp `max_tokens`; `402` for every refusal.* Sub-question the operator must answer explicitly: **does jobs-mcp's public `status(id).spent_usd` mean list-equivalent USD (same unit as `budget_cap`, checkable on every lane; the invoice one field away in `result`) or billed USD (the free lane reports 0)?** This spec recommends list-equivalent. Alternatives — billed dollars as the unit (a `$0` cap then bounds nothing on the free lane); settle-at-end (N concurrent requests jointly overshoot); clamping `max_tokens` (silent truncation).
6. **Compatible surface.** *`/v1/chat/completions` + `/v1/models`; sampling parameters stripped-and-declared; buffered `stream`; `json_schema` honoured on both lanes; tools, `n`, `logprobs`, media and server tools rejected by name; `/v1/embeddings` declared `501`; the CLI lane honours text-in/text-out + JSON schema only.* Alternative — full compatibility (streaming, tools, images, embeddings): each adds translation code with no v1 consumer and, for tools, a second billing shape; each has a §11 tripwire.
7. **Caller authentication.** *The house caller-token JSON map as the client's `api_key`; classes `operator | executor | worker | lane-agent`, closed at admission, no `frontend`; job scope `(caller_id, job_id)`; per-class ceilings ARE the blast radius (§5 table); NetworkPolicy and an ACL grant list as later, proven steps; WhoIs a seam.* Alternative — a scalar bearer: three callers on day one and the atomic reshape the knowledge spec avoided.
8. **Request log.** *The ledger row, metadata only — no text, no prompt hash, no `user` field — kept indefinitely; pruning an explicit destructive task; operator-class read endpoints.* Alternatives — storing completions for idempotent replay (correspondent text on an unbacked-up volume for a feature with no consumer); a daily auto-prune (a destructive operation folded into steady state on the one file that is enforcement state).
9. **Subscription-lane terms and quota.** *Mechanism only in the repo: the unmodified binary on the box that minted the token, never intermediated, `operator`-class only, bounded in list-USD by the registry windows and the daily brake; the operator records a one-line attestation before slice 4 and sends the vendor's own channel the question, its answer recorded when it arrives.* Alternatives — skip slice 4 until the vendor answers (zero policy risk; the $0 lane waits; slices 1–3 unchanged); executors or workers on the lane (more $0 work, more contention with interactive use, and a terms question this spec will not answer on the operator's behalf).
